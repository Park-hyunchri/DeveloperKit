# 운영 공통 표준

## 운영 로그 보존과 자동 정리

- 운영 로그 보존 기간은 최대 6개월을 기본값으로 한다.
- 애플리케이션 시작 시 1회, 장기 실행 중에는 24시간마다 정리 여부를 확인한다.
- 현재 시각 기준 6개월보다 오래된 파일만 정리한다.
- 애플리케이션이 직접 관리하는 전용 로그 디렉터리와 알려진 로그 확장자만 대상으로 한다.
- 경로를 정규화하고 대상 로그 디렉터리 내부인지 확인한 후 삭제한다.
- 사용 중인 파일과 정리 실패 항목은 건너뛰고 경고를 남기며 애플리케이션 실행은 계속한다.
- 고객·법규·계약 요건에 따라 보존 기간을 줄일 수 있다. 6개월 초과 보관은 근거와 승인 내역을 문서화한다.
- 로그에 암호, 토큰, 개인정보 등 민감정보를 기록하지 않는다.

## 자동 버전

- 배포 버전의 기준은 Git 태그 `vMAJOR.MINOR.PATCH`로 한다.
- 빌드·게시 자동화가 태그와 커밋 정보를 읽어 `Version`과 추적 가능한 커밋 정보를 주입한다.
- 프로젝트 파일을 빌드 과정에서 수정하지 않는다.
- 태그 없는 빌드는 시험용 사전 릴리스 버전으로 구분하고 운영 배포하지 않는다.
- 같은 커밋과 입력으로 생성된 결과물은 같은 버전을 가져야 한다.

## 권장 최상위 폴더 구조

```text
<project>/
├─ src/       소스 코드
├─ tests/     자동화 테스트
├─ docs/      설계·운영 문서
├─ scripts/   빌드·점검 자동화
└─ deploy/    배포 설정과 패키징 자료
```

이 구조는 신규 프로젝트의 권장안이다. 기존 프로젝트는 구조를 변경하지 않고 현재 위치를 문서화한다.
