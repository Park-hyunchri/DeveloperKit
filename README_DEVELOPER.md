# 개발자 가이드

## 프로젝트 구조

신규 프로젝트는 소스 `src`, 테스트 `tests`, 설계·운영 기록 `docs`, 자동화 `scripts`, 배포 자료 `deploy`를 권장 최상위 폴더로 사용한다. 기존 프로젝트는 현재 구조를 유지한다.

## 개발 원칙

- C# / WPF / MVVM 구조 유지
- View는 표시와 사용자 입력, ViewModel은 상태와 명령, Model은 데이터와 규칙 담당
- 기존 동작을 보존하고 필요한 부분만 수정

## 작업 방법

`AGENTS.md` 확인 → 원인 분석 → 영향 범위와 테스트 계획 설명 → 승인 → 수정 → 빌드/테스트 → 기록 갱신

## Git 규칙

작업 전후 `git status`와 `git diff`를 확인한다. Commit과 Push는 사용자가 명시적으로 요청한 경우에만 한다.

## 빌드와 실행

각 프로젝트의 솔루션과 README에 정의된 명령을 사용한다. 환경별 설정과 배포·복구 절차는 프로젝트별 `배포방법.md`에 기록한다. 자동 버전은 Git 태그를 기준으로 빌드·게시 명령에서 주입하며 프로젝트 파일을 자동 변경하지 않는다.

## 운영 로그

운영 로그는 최대 6개월 보관을 기본으로 하며, 애플리케이션이 직접 생성한 로그만 안전하게 정리한다. 상세 기준은 `docs/OperationalStandards.md`를 따른다.
